Mean vs P95 latency, per format

End-to-end wall-clock time per image (load + preprocess + inference + postprocess), log scale. P95 shows the tail a real-time system has to budget for, not just the average.

Latency stage breakdown

Mean time spent in each stage of the pipeline, as reported by the model itself. Each format has its own scale — the story here is composition, not cross-format comparison (see the latency chart above for that).

Latency percentiles (tail behavior)

p50 / p90 / p95 / p99 of end-to-end latency, log scale. A steep climb from p50 to p99 means occasional slow frames — worth knowing before trusting a single "avg FPS" number.

Per-frame latency (stability over the run)

Wall-clock latency for each of the 100 sampled frames, in run order. Each format has its own y-scale. Periodic spikes (roughly every 10–13 frames on PT and Engine) point to a system-level effect — e.g. Jetson clock/DVFS scaling — rather than the model itself; worth a closer look with jetson_clocks/nvpmodel if consistent per-frame latency matters for the car.
